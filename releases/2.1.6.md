## provider minor 2.1.6

### Добавлено

1. Расширена поддержка mcm: диски и их подключение, образы, сети, подсети, публичные IP-адреса и их подключение.

### Исправлено

1. Приведены к единому формату имена типов ресурсов Data Platform:
   - `cloudru_evolution_cluster_cluster` → `cloudru_evolution_data_platform_cluster`.
   - `cloudru_evolution_bi_bi` → `cloudru_evolution_data_platform_bi`.
   - `cloudru_evolution_spark_spark` → `cloudru_evolution_data_platform_spark`.
   - `cloudru_evolution_spark_spark_connect` → `cloudru_evolution_data_platform_spark_connect`.
   - `cloudru_evolution_trino_catalog` → `cloudru_evolution_data_platform_trino_catalog`.
   - `cloudru_evolution_trino_trino` → `cloudru_evolution_data_platform_trino`.
   - `cloudru_evolution_metastore_metastore` → `cloudru_evolution_data_platform_metastore`.
2. Аналогично переименованы датасорсы кластеров Data Platform, BI, Spark, Trino, каталогов Trino и Metastore: используются новые имена ресурсов с суффиксом `_collection`.
3. Добавлен префикс `data_platform_` в имена датасорсов конфигураций BI, Spark, Trino и Metastore (`bi_flavor_collection`, `spark_flavor_collection`, `trino_flavor_collection`, `metastore_flavor_collection`), базовых образов Spark (`spark_base_image_collection`) и версий Spark и Trino (`spark_version_collection`, `trino_version_collection`). Полные имена начинаются с `cloudru_evolution_data_platform_`.

4. Секреты ресурсов `cloudru_evolution_iam_access_key` и `cloudru_evolution_iam_api_key`, а также пароли пользователей Kafka, PostgreSQL и ClickHouse помечены как чувствительные: их значения скрываются в обычном выводе `terraform plan` и `terraform apply`.
5. Секреты IAM access key и API key сохраняются в Terraform state после `refresh` и обновления ресурса, даже если API больше не возвращает их. При импорте секрет остаётся `null`, поскольку получить его повторно через API нельзя.
6. В gRPC-логах провайдера чувствительные значения в запросах, ответах и ошибках маскируются. Остальные данные запроса и ответа остаются доступны для отладки.
7. Исправлено планирование сетевого интерфейса Compute VM: изменение его идентификатора требует пересоздания ресурса.
8. Конфигурация Spark Connect стала `Optional + Computed`, чтобы сохранять значения, возвращаемые API.
9. Исправлена обработка неизвестных значений вложенных блоков `retention_policy` и `upstream` в Artifact Registry.
10. Исправлены миграция и импорт ресурсов MK8s.

При обновлении замените прежние имена типов в блоках `resource` и `data`, а также в ссылках на них. Прежние имена больше не регистрируются провайдером.

### Документация

1. Обновлены имена файлов и примеры в справочнике для 7 ресурсов и 13 датасорсов Data Platform в соответствии с новыми именами типов.
2. Добавлены пояснения к зависимостям ресурсов Kafka: выбор версии кластера, идентификатора спецификации и т.д.
3. Добавлены пояснения к зависимостиям ресурсов Magic Router: выбор целевого идентификатора Magic Router'а, маршрута подключения через VPC и т.д.
4. Добавлены пояснения к зависимостям ресурсов Managed Kubernetes: значения для зон плоскости, версии CNI, KEK ID и т.д.
5. Добавлены пояснения к зависимостям ресурсов Load balancer: выбор идентификаторов подсетей, целевой группы, сетевого интерфейса и т.д.
6. Дополнены пояснения к зависимостям ресурса Managed BI: выбор типа конфигурации вычислительной мощности, идентификатор кластера и т.д.
7. Добавлены пояснения к зависимостям ресурсов Data Platform (Managed Spark, Managed Metastore, Managed Trino): сетевые настройки кластеров, параметры конфигурации вычислительных ресурсов и т.д.
8. Добавлены практические руководства "Развертывание Kafka, Redis и DNS в приватной сети с помощью Terraform" и "Развертывание Managed PostgreSQL с помощью Terraform".
9. Обновлены описания и примеры ресурсов и датасорсов mcm.
10. Добавлено [руководство по чувствительным данным](../guides/sensitive-data.md): хранение секретов в state, импорт ключей и маскирование логов.
