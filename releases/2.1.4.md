## provider minor 2.1.4

### Добавлено

1. Поддержка BI: ресурс `cloudru_evolution_bi_bi` для управления экземплярами и датасорсы `cloudru_evolution_bi_bi_collection` и `cloudru_evolution_bi_flavor_collection` для получения экземпляров и доступных конфигураций.
2. Поддержка ClickHouse: ресурсы `cloudru_evolution_clickhouse_cluster`, `cloudru_evolution_clickhouse_database` и `cloudru_evolution_clickhouse_user`. Добавлены датасорсы для получения кластеров, баз данных, пользователей, ролей, конфигураций и версий ClickHouse.
3. Настройка разметки дисков Bare Metal через поле `partitions` ресурса `cloudru_evolution_baremetal_reserved_server`: выбор дисков, RAID, логических томов, файловых систем и точек монтирования. Информация о разметке также доступна в датасорсе `cloudru_evolution_baremetal_reserved_server_collection`.
4. Добавлены эндпоинты по умолчанию для PostgreSQL, ClickHouse, Data Platform, BI и Object Storage User Plane API.
5. Добавлена понятная ошибка при отсутствии или пустом значении эндпоинта используемого ресурса или датасорса с подсказкой, какое поле указать в `endpoints`.
6. Добавили поддержку переменных окружения `AUTH_KEY_ID` и `AUTH_SECRET` для аутентификации провайдера. Параметры `auth_key_id` и `auth_secret` стали опциональными: значения из конфигурации имеют приоритет, а для каждого неуказанного параметра используется соответствующая переменная окружения.
7. Поддержка VirtualIP: ресурс `cloudru_evolution_vpc_vip` для управления виртуальными IP-адресами и датасорс `cloudru_evolution_vpc_vip_collection` для получения их списка.

### Исправлено

1. Исправлено сохранение промежуточного state при создании и обновлении ресурсов с вложенными computed-полями, в том числе внутри коллекций. При ошибке ожидания асинхронной операции неизвестные computed-значения корректно заменяются на `null`, а идентификатор ресурса сохраняется. Это устраняет дополнительные ошибки консистентности Terraform, связанные с такими полями, например `disk_type.free_tier` у диска Compute.
2. Исправлено планирование изменений неизменяемых параметров MK8s. Для `cloudru_evolution_mk8s_cluster` изменения `control_plane.zones`, `control_plane.version`, `network_configuration.services_subnet_cidr`, `network_configuration.pods_subnet_cidr`, `network_configuration.kube_api_internet`, `network_configuration.private_vip_subnet_id` и `bootstrap_managed_addons` теперь приводят к пересозданию кластера, а не к попытке обновления на месте.
3. Для `cloudru_evolution_mk8s_node_pool` изменения `network_configuration.nodes_subnet_id` и `network_configuration.security_group_id` теперь приводят к пересозданию группы узлов. Перед применением таких изменений проверяйте действия в `terraform plan`.
4. Блок `endpoints` теперь переопределяет только указанные значения, сохраняя дефолтные адреса остальных сервисов. Поле `iam_endpoint` в этом блоке стало необязательным.
5. Исправлено имя дефолтного ключа эндпоинта Organization: `cloud_platform_endpoint`.
6. Устранено влияние переопределений IAM и Resource Manager на другие конфигурации провайдера.
7. Добавили проверку параметров аутентификации: если после чтения конфигурации и переменных окружения `auth_key_id` или `auth_secret` пустой, провайдер возвращает ошибку с указанием недостающего параметра.

### Документация

1. Добавлено руководство по миграции с версии 1.x на 2.x.
2. Добавлена документация о принципах работы Terraform-провайдера.
3. Добавлены описания и примеры использования ресурсов и датасорсов BI и ClickHouse.
4. Добавлены пояснения к зависимостям ресурсов Compute: выбор зон, типов дисков, образов, сетей и групп безопасности, а также заполнение метаданных образа при создании ВМ.
5. Добавлены пояснения к зависимостям ресурсов Baremetal: выбор зон, ядра операционной системы, подсетей и т.д.
6. Добавлены пояснения к зависимостям ресурсов PostgreSQL: выбор версии, подсетей, идентификаторов спецификаций и т.д.
7. Добавлены пояснения к зависимостям ресурсов IAM: идентификаторы сервисного аккаунта, проекта, организации и т.д.
8. Обновили пример `docs/reference/main.tf`: описали опциональность `auth_key_id` и `auth_secret`, приоритет конфигурации и использование переменных окружения.
