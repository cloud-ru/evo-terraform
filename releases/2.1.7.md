## provider patch 2.1.7

### Добавлено

1. Для запросов S3 добавлены заголовки `x-request-id` и `x-request-initiator`. В отладочных логах `tflog` теперь видны идентификатор запроса, статус ответа и XML запросов и ответов для правил жизненного цикла бакета.

2. Добавлена настройка сертификатов подключения: `ca_cert_file` задаёт PEM-файл доверенных CA, а `client_cert_file` и `client_key_file` — клиентский сертификат и ключ для mTLS. Пути также можно задать через `CA_CERT_FILE`, `CLIENT_CERT_FILE` и `CLIENT_KEY_FILE`; явные значения в конфигурации имеют приоритет. Без этих настроек используются системные доверенные CA, клиентский сертификат не требуется.

### Исправлено

1. Исправлено заполнение Terraform state при импорте Bare Metal: для `cloudru_evolution_baremetal_reserved_server` поля `flavor_id`, `zone_id`, `subnet_id`, `ip_id` и `log_group_id` восстанавливаются из вложенных объектов ответа API; для `cloudru_evolution_baremetal_subnet` восстанавливается `zone_id`. Значения заполняются, если соответствующие данные возвращает API.
2. Для `cloudru_evolution_compute_security_group_rule` поле `security_group_id` при импорте заполняется из `security_group.id` ответа API.
3. Для `cloudru_evolution_magic_router_static_route` поле `vpc_connection_id` при импорте восстанавливается из `next_hop_vpc.vpc_connection_id`. Исправлена обработка вложенного варианта `next_hop_vpc` в ответе API.
4. Исправлено восстановление версии при импорте ресурсов Data Platform: `version_id` у `cloudru_evolution_data_platform_metastore`, `cloudru_evolution_data_platform_spark` и `cloudru_evolution_data_platform_trino`, а также `update_id` у `cloudru_evolution_data_platform_bi` заполняются из объекта версии в ответе API.
5. Для `cloudru_evolution_iam_permission` при импорте восстанавливается вложенный объект `role_identifier`: используется `role_id` из `primary_role_id` ответа API, а при его отсутствии — `role_name`. Уже заданный в конфигурации вариант `role_identifier` сохраняется.
6. Уточнены сообщения об ошибках запроса `Get`, выполняемого после создания или обновления ресурса: сообщение указывает Terraform-операцию `Create` или `Update` и уточняет, что сбой произошёл при получении ресурса.
7. Для `cloudru_evolution_obs_bucket` поле `lifecycle_rules.prefix` теперь передаётся в XML запроса S3 и сохраняется в state. Если префикс не задан, провайдер передаёт пустой `Prefix`, и правило применяется ко всем объектам бакета. Непустой `prefix` нельзя сочетать с `filter`; если заданы оба, оставьте один способ фильтрации.
8. Для `cloudru_evolution_obs_bucket` неуказанные `quota`, `quota_type` и `quota_unit` после создания и обновления становятся `null`. Terraform больше не получает ошибку о неизвестных значениях этих полей после `apply`.
9. Для `cloudru_evolution_compute_interface` поле `security_groups` стало необязательным. Исправлена передача групп безопасности и заполнение state: `null` и неизвестное значение не создают обёртку в запросе, а явно заданный `[]` передаёт пустой список для очистки групп при включённой защите. Пустой и непустой списки из ответа API корректно сохраняются в state.
10. Для `cloudru_evolution_compute_interface` значение `interface_security_enabled` по умолчанию — `true`. При включённой защите `security_groups` может отсутствовать, быть `null`, пустым или непустым списком: переключить защиту с `false` на `true` можно без передачи групп, а назначить их отдельным обновлением. Если защита должна оставаться выключенной, явно укажите `interface_security_enabled = false`.
11. Для `cloudru_evolution_compute_interface` добавлена проверка конфигурации до обращения к API: при `interface_security_enabled = false` нельзя задавать `security_groups`, включая `[]`. При обновлении таких конфигураций удалите поле или задайте `null`. Проверка неизвестных значений откладывается до их определения.
12. У ресурса `cloudru_evolution_compute_vm` и датасорса `cloudru_evolution_compute_vm_collection` поле `network_interfaces` переведено из списка в множество (`Set`), чтобы перестановка интерфейсов в ответе API не приводила к расхождению коллекции Terraform. При обновлении замените обращения по индексу, например `network_interfaces[0]`, выбором интерфейса по его атрибутам.

13. Поле `password` ресурса `cloudru_evolution_baremetal_reserved_server` помечено как чувствительное: значение скрыто в обычном выводе `plan` и `apply`, но остаётся в state.
14. Для `cloudru_evolution_clickhouse_user` и `cloudru_evolution_clickhouse_user_collection` поле `granted_roles.value` теперь хранится как множество строк: порядок ролей в ответе API больше не влияет на сравнение значений. Для ресурса добавлены значение `granted_roles` по умолчанию и обработка неизвестного блока. При обновлении замените обращения к `granted_roles.value` по индексу: множества не поддерживают индексы.
15. Для `cloudru_evolution_clickhouse_cluster` неизвестные блоки `config` и `logging` при создании, а также `config` при обновлении больше не передаются в API как пустые объекты.
16. Для `cloudru_evolution_mk8s_node_pool` исправлена ошибка с пустым параметром `initial_count`.
17. Для `cloudru_evolution_mk8s_node_pool` исправлены ошибки с параметрами `labels` и `tains`.

### Документация

1. Для `cloudru_evolution_compute_interface` описаны правила совместного использования `interface_security_enabled` и `security_groups`, очистка групп и включение защиты без передачи групп. Уточнены значения поля `type`: `INTERFACE_TYPE_DIRECT_IP` и `INTERFACE_TYPE_REGULAR`.
2. В справочной документации `cloudru_evolution_compute_vm` и `cloudru_evolution_compute_vm_collection` отражён тип `Set` у `network_interfaces`.
3. Добавлены пояснения к зависимостям ресурсов Artifact Registry, Redis, VPC, Organization и Resource Manager: откуда получить идентификаторы и как выбрать связанные объекты.
4. Уточнена документация IAM: требования к именам групп и сервисных аккаунтов, выбор роли и области назначения разрешений.
5. В навигацию практических руководств добавлен сценарий настройки Magic Router через Terraform.
