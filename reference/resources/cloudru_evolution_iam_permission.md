## Зависимости

### Resource ID

``resource_id`` - идентификатор ресурса, на который выдается доступ. Может быть идентификатором организации, проекта или любого ресурса в проекте. Выберите его из ``id`` соответствующего датасорса, если такой датасорс предусмотрен для нужного типа ресурса.

### Subject ID

Поле ``subject_id`` - идентификатор пользователя, группы или сервисного аккаунта. Его можно получить из:

- ``users.id`` из датасорса ``cloudru_evolution_iam_user_collection`` (нужен ``customer_id`` для получения)
- ``groups.id`` из датасорса ``cloudru_evolution_iam_group_collection`` (нужен ``target`` с ``customer_id`` или ``project_id`` для получения)
- ``service_accounts.id`` из датасорса ``cloudru_evolution_iam_service_account_collection`` (нужен ``target`` с ``customer_id`` или ``project_id`` для получения)

## Назначение роли

Как использовать данный ресурс для назначение роли для пользоватля, группы или сервисного аккаунта:

1. Создайте пользователя, группу или сервисный аккаунт
2. Передайте его `id` в поле `subject_id`
3. В `resource_id` укажите идентификатор организации, проекта или ресурса, к которому предоставляется доступ.
4. Укажите роль в `role_identifier`:
   - `role_name` — для продуктовой роли
   - `role_id` — для пользовательской роли или при совпадении имён ролей

Пример:
```
resource "cloudru_evolution_iam_permission" "permission" {
  subject_id = cloudru_evolution_iam_service_account.test.id
  resource_id = var.project_id

  role_identifier = {
    role_name = "project.viewer"
  }
}
```

Один ресурс `cloudru_evolution_iam_permission` назначает одну роль на один ресурс.

Изменение роли, `subject_id` или `resource_id` приводит к пересозданию `permission`. Для отзыва роли удалите соответствующий ресурс из конфигурации.
